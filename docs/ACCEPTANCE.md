# Snapshot Compare：方案與成果驗收標準

擴充／重構／功能開關另須逐項驗收 [EXTENSION-CONTRACT.md](EXTENSION-CONTRACT.md) 的 X1–X8；lint、型別、行為與實際畫面證據不可互相替代。

版本：v1.1，2026-11-19。加入使用者確認的特殊 node 與避免誤導的驗收；適用於 Snapshot Compare 的每次方案 review、原型 review、實作與整合 review。

目標：審查者能準確、有效率且舒適地理解文件變更，不需重讀整份文件。美感、清晰度、正確性與可操作性共同構成品質，不能互相抵銷。

本文件是目前範圍的完整驗收基準，不宣稱涵蓋未發現的產品情境。新問題先記錄證據與影響；不得為了讓方案通過，事後降低標準或悄悄排除失敗案例。範圍與驗收要求的實質變更須回到使用者討論。

## 1. 範圍與證據界線

- 使用者確認每版保存完整 Lexical JSON；尚未獨立查驗正式產品的 registry、snapshot 或 renderer。
- 初期只涵蓋功能啟用後、符合明確比較契約的新版本；不要求回補既有歷史。
- 任選兩版是期望流程，可延後。第一版允許的版本配對規則須明示，不能在 UI 暗示未支援的能力。
- 初期精準比較：文字／數字、連結目的地、簡單表格儲存格。格式變更必須可見；不要求所有格式都有精細標記。
- 搬移、重複區塊、複雜表格、圖像／Mermaid、自訂未知節點允許完整前後對照或明確標示未能驗證；不得隱藏差異或虛構精準配對。
- 使用者確認有 image、video、合併儲存格 table、mermaid、quote、collapse 等特殊 node。實際序列化欄位、可巢狀組合與 renderer 尚待產品查驗；以下是驗收情境，不是對產品 schema 的推定。
- Markdown 匯入、Track Changes、逐項接受／拒絕、AI 摘要、審批流程重設、舊歷史遷移不在初期範圍。
- 不預定必須加入持久 ID、使用特定 diff 演算法或全站統一左右兩欄。選擇須服務以下任務。

## 2. 每次 review 的固定判定方式

每次 review 均複製 [REVIEW-TEMPLATE.md](REVIEW-TEMPLATE.md)，列出全部標準 ID。每項只能標示：

| 狀態 | 定義 |
| --- | --- |
| 通過 | 本階段要求的證據可重現、符合接受條件；附連結或具體位置。 |
| 不符合 | 有反例或缺陷；指出看到什麼、影響哪個審查任務。 |
| 待驗證 | 證據不足或尚未執行；不能計為通過。 |
| 不適用 | 由已確認範圍決定；附理由。困難、時間不足、尚未完成不是不適用。 |

每次重查完整清單，但不必重跑所有測試：未變更且仍有效的證據可引用，須說明來源版本、適用範圍與未受影響的理由。資料、版面、adapter 或 renderer 改變時，重新檢查受影響案例。每次至少核對目前實際畫面與整體視覺品質，不能只引用舊截圖。

總結只能是「本階段通過」「需修改」「證據不足」。不得以平均分數抵銷任何必需項的不符合，也不得以「有條件通過」隱藏缺證。視覺方案通過不等於實作或產品通過。

### 各階段需要的證據

| 階段 | 本階段必需證據 | 不能宣稱的事 |
| --- | --- | --- |
| D：體驗／視覺方案 | 固定案例與獨立答案；案例 1–5 與對照的代表畫面或明確狀態稿；真實長度內容；互動／fallback 規格；完整視覺規則。設計階段可先以案例 1、2、5 同內容比較兩種布局，再讓候選方案覆蓋所有案例。 | mockup 不能證明引擎正確、互動可用或真人易用。 |
| P：可操作切片 | 六組核心案例及第3.1節特殊 node 案例的實際 JSON → 引擎 → 畫面證據；可操作入口、版本資訊、走查紀錄；正常／密集／錯誤狀態；鍵盤與縮放檢查。特殊 node 可驗收保守 fallback，不要求精準 diff。 | agent 檢查不能證明真人理解或正式產品相容。 |
| H：真人價值驗證 | 未參與設計的代表性 reviewer 無提示完成任務；逐人答案、錯誤、求助、時間及視覺感受；與目前開兩版方式比較時使用相當任務、平衡順序。招募條件與規模在執行前記錄。 | 少量質性試用不能宣稱普遍效率增益、統計顯著或所有使用者都容易理解。 |
| I：產品整合／交付 | 真實 registry、儲存資料、revision API、唯讀 renderer 與權限證據；瀏覽器相容與代表性大小量測；重跑受影響案例；之前的 H 結論仍適用。 | 合成案例與實驗室通過不能代替產品證據。 |

每個標準在 D 階段檢查「畫面與行為是否定義完整」，在 P 階段檢查實際行為。H、I 特有的證據可在早期標待驗證，不阻止較早階段通過，但不得省略。重大實作仍須取得使用者對方向與範圍的明確對齊。

## 3. 固定使用者案例與答案

全部使用合成「服務上線與維運規範」。先保存答案與預期變更，再製作 snapshot 或引擎結果；不得從實作輸出反推正確答案。參與者只能看任務，不能先看答案。

| 案例 | 固定變更與任務 | 可接受 | 不符合 |
| --- | --- | --- | --- |
| C1 小改字、大改義 | 保留 30 天→7 天；刪除「刪除前須經資料擁有人核准」。任務：說明期限及刪除條件變化。 | 兩項都被找到；完整句意與刪除條件可讀；不用另開舊版。 | 只找到數字；刪掉的句子消失；方向顛倒；只能看到碎字。 |
| C2 表格承諾變更 | 指定服務回應 4→8 小時、全天→工作日，並新增另一服務列。任務：指出哪項服務的承諾改變。 | 能同時確認服務、列欄、舊新值；插列不誤報後面每列修改。 | 值正確但歸錯服務；整表高亮掩蓋兩格變更；無法恢復標頭脈絡。 |
| C3 名稱不變、目的地改變 | 「正式環境操作手冊」連結改指測試環境文件。任務：確認操作依據是否改變。 | 不點開外部文件也知道目的地變了；能查看完整舊新 URL。 | 顯示無變更；只標文字；必須逐一開啟才能發現。 |
| C4 整理中藏規則修改 | 章節搬移、粗體與清單格式調整；「失敗時必須回復」→「失敗時可以回復」。任務：區分整理與規則變化。 | 規則變更能被找到及讀懂；格式變更有入口；配對不明時提供完整對照與限制。 | 噪音淹沒關鍵修改；斷言無法證明的搬移；隱藏格式改變。 |
| C5 無法精準比較 | Mermaid 移除核准步驟、未知自訂區塊改變、一版預覽失敗。任務：指出變動及仍需人工確認的區域。 | 可定位各區域；有可用前後內容／來源；明示未驗證與預覽失敗。 | 當作相同或完整成功；只有籠統警告；假裝已理解未知內容。 |
| C0 相同內容 | 支援範圍內兩版內容相同。任務：判斷是否有內容變更。 | 清楚顯示未偵測到變更及比較範圍，不產生假差異。 | 全標紅以避免漏報；把未比較區域也宣告無變更。 |

未知但 payload 相同的額外對照，應顯示「資料相同、語意未驗證」，不得套用 C0 的完整無變更結論。

### 3.1 特殊 node：先保證不誤導

共同原則：**寧可說明這個區塊有變動、請看前後內容，也不能顯示沒有根據的細部差異。** 但不能把整份文件全部降級為 raw JSON；應降級到能可靠定位、保留上下文的最小完整區域。若連區域配對也不確定，擴大到共同容器或章節，明示原因，不能假設舊新節點一對一。

區分三種結論：①已驗證的具體變更；②已知資料／結構變動，但未精準配對；③來源或 renderer 不足，內容無法驗證。未知不是相同，也不是已知不同。只呈現來源文字不能宣稱已理解圖像、影片或流程語意。

| 案例 | 審查任務與變更 | 可接受 | 不符合 |
| --- | --- | --- | --- |
| N1 Image | 操作截圖被替換；另測只有說明／替代文字變更，以及相同 URL 的外部內容無版本證據。任務：確認操作圖與描述是否仍適用。 | 分開顯示已知來源／描述變更與前後預覽；舊圖取不到時明示，不能借用新圖。無版本證據時說明無法確認圖像內容。 | 兩側載入同一張現行圖片卻標為歷史前後；像素或語意變更憑空推定；同 URL 就說未變。 |
| N2 Video | 教學影片來源替換、封面／標題變更；舊影片失效。任務：判斷操作教學依據是否變動及哪些內容尚需觀看。 | 已知來源與 metadata 變更分開呈現；可用時提供前後播放器／入口，無法取得則保留身分與限制；不宣稱鏡頭級差異。 | 封面相同就說影片相同；連結失效等於內容刪除；播放新版冒充舊版。 |
| N3 Merged table | 規範表合併／拆分列欄、調整 span，部分文字不變，另改一個數值。任務：判斷規則適用範圍是否改變。 | 結構變動可見；不確定格子對應時顯示兩份完整表格，保留各自標頭與合併形狀，提醒人工核對數值。 | flatten 後文字一樣就說未變；按陣列 index 錯配；高亮跨格導致範圍誤解。 |
| N4 Mermaid | 移除核准步驟／改連線；另測來源不變但渲染布局改變，以及一側語法錯誤。任務：辨認流程資料改動與尚未驗證部分。 | 比較來源；預覽可得時供核對，失敗不隱藏來源；布局差異不冒充流程修改。 | 憑 SVG 位置差異宣稱節點搬移／邏輯變更；渲染失敗當相同；未解析語意卻給肯定摘要。 |
| N5 Quote | 引用中刪除例外條件；相同文字從 quote 變為普通段落或移出 quote。任務：確認引述的條件與歸屬是否改變。 | 保留引用邊界、層級與上下文；文字 diff 有可靠配對才細分，容器變更需可見。 | 展平後忽略引用結構；把引文與作者正文配成同段；例外條件消失不提示。 |
| N6 Collapse | 標題不變但收合內容的規則／巢狀 node 改變，或整個 collapse 被刪除。任務：找到預設隱藏的變動。 | 收合狀態仍可看見變更／未驗證提示；導覽能展開抵達；刪除容器的舊內容可讀。互動開合不改寫 snapshot。 | 只比可見 DOM；標題沒變就算相同；收起時漏計差異；把使用者本次展開操作當文件編輯。 |
| N7 巢狀與故障隔離 | collapse 內含 quote、合併表格與失效媒體；其中改數值，外部再改一段普通文字。任務：辨認已確認變更與仍需人工核對區域。 | 外部文字維持精準比較；容器內能定位變動／限制，不因折疊或一個 renderer 失敗隱藏其他內容；實際產品不允許的巢狀需換成允許的等價組合並記錄依據。 | 一個 node 失敗讓整頁顯示無變更；跨容器亂配；只剩籠統警告，無法找到受影響內容。 |

每種類型至少檢查：新增、刪除、修改、完全相同四種狀態；另依表格加入結構／來源／故障反例。這些可做成參數化 fixtures，不必增加同等數量的真人任務或逐一製作全新布局。D 階段至少展示媒體、合併表格與收合巢狀三種代表性 fallback 畫面，並規定其餘行為；P 階段每種類型都要有可重現證據。H 至少安排一次找出折疊變更、一次解讀媒體或複雜表格限制的任務。

如果 collapse 開合旗標有保存，必須由產品語意決定它是內容設定還是可忽略的檢視狀態並寫入欄位政策，不能自行忽略。來源／簽名 URL 等欄位亦同；URL 不同不必然表示媒體位元組不同。未知 schema 的 payload 相同只能證明保存資料相同。

## 4. 逐項驗收清單

### 範圍、資料與正確性

| ID | 可接受 | 不符合 | 必要證據 |
| --- | --- | --- | --- |
| S1 版本與方向 | A→B 的身分、可用日期等資訊清楚；固定 immutable pair；支援邊界可見。 | 「目前版本」偷偷變動；舊新相反；不支援的歷史仍可進入假結果。 | D 狀態稿；P 切換版本與過期請求測試；I revision API。 |
| S2 範圍誠實 | 精準／粗略／未驗證區域及原因可區分；限制不隨篩選消失。 | 部分結果當完整；宣稱完整還原編輯歷程或逐項作者。 | 各狀態畫面與 C5。 |
| C1 內容保真 | 所有故意變更準確呈現或可定位 fallback；C1–3 核心精準任務不能只交整份 raw JSON。 | 漏掉數字、否定、條件、URL；錯配舊新；只給開發者能讀的差異。 | 獨立答案、fixtures、引擎 assertions、實際畫面對照。 |
| C2 欄位政策 | 每種欄位有比較／經證明可忽略／不支援政策；未支援內容保留。 | 重用會丟格式的 normalizer；靜默刪除不認識欄位。 | adapter 欄位清單與反例；D 可先列需求，P 實測。 |
| C3 配對與噪音 | 重複段落、插列、搬移不確定時採誠實 fallback；支援且未變內容不誤標。 | 位置相同就假設同區塊；整份誤報；虛構穩定身份。 | C2、C4、C0；若採 ID，另測新增／複製貼上／拆合／重載。 |
| C4 表格與連結 | C2 的列欄舊新值可讀；C3 完整目的地可展開；複雜表格有前後對照。 | 改錯列；截斷 URL 且無查看方式；跨儲存格標記破壞結構。 | 表格與長 URL 實際畫面／互動。 |
| C5 圖像與未知內容 | 來源／metadata 變更可見；預覽錯誤仍有證據入口；外部資產未版本化時說明限制。 | 同 URL 即聲稱圖像相同；render 失敗丟內容；原始碼當所有使用者都已理解。 | C5、資產版本政策；I host renderer 證據。 |
| C6 唯讀與安全 | 比較不改寫 snapshot／現行文件；使用既有安全渲染政策；歷史存取權在 host 驗證。 | diff 污染保存資料；直接執行不可信 HTML/SVG；舊版繞過權限。 | P 前後輸入一致性與失敗測試；I 權限／渲染檢查。 |
| C7 特殊 node 不誤導 | N1–N7 依已知／粗略／未驗證分類；結構保留；粗略結果不標成精準差異。 | 錯配媒體／儲存格／引用；隱藏 collapse 內變更；把未知當相同或把預覽差異當內容差異。 | 第3.1節各型新增／刪除／修改／相同與反例證據；I 真實 schema 對應。 |
| U7 Fallback 可閱讀 | 明示哪一區域、為何無法精準比較、可看哪些前後內容；視覺品質與普通 diff 一致，導覽可抵達隱藏內容。 | 只有「不支援」或 raw JSON；前後方向不明；失敗佔位冒充原內容；粗略色塊暗示所有字都變了。 | D 三種代表畫面；P N3、N6、N7 操作；H 限制理解任務。 |

### 閱讀與操作體驗

| ID | 可接受 | 不符合 | 必要證據 |
| --- | --- | --- | --- |
| U1 定向 | 進入即可辨認比較對象、方向、完整性及如何開始閱讀。 | 版本藏於 hover；工具列比內容醒目；需口頭導覽才知道用途。 | 首屏畫面；H 無提示定向任務。 |
| U2 導覽 | 能從變更導覽抵達正確位置；下一／上一項、目前位置與上下文關係清楚。 | 跳錯區塊、焦點丟失、標頭遮住變更、只能手動通篇尋找。 | P 鍵盤／滑鼠走查，包含長文件。 |
| U3 完整句意 | 刪除內容與新增內容可讀；未變段落可展開；保留章節脈絡。 | 只有碎字或整片色塊；收合導致理解歧義且不能展開。 | C1、C4 的閱讀路徑。 |
| U4 減少噪音 | 可聚焦內容變更；篩選／收合狀態明示，仍能找回所有變更與限制。 | 格式噪音蓋過規則修改；篩選後假稱沒有任何變更。 | C4 的初始／篩選／展開畫面。 |
| U5 狀態與復原 | 載入、無變更、部分成功、錯誤、重試可區分；切版不顯示上一次的假結果。 | 空白當無變更；永久 loading；失敗後無返回或重試路徑。 | 狀態稿；P 延遲、失敗、切版操作。 |
| U6 可達性與縮放 | 核心流程鍵盤可完成，焦點可見、控制有名稱；200% 縮放仍可操作；寬表格可局部捲動。 | 只靠 hover／顏色；焦點不可見；控件重疊、必要文字被裁掉。 | P 鍵盤與200%縮放，記錄 viewport；不宣稱完整 WCAG 認證。 |

## 5. 每次 review 必交的最小證據包

1. 方案／實作版本、review 階段、範圍、日期與 reviewer 身分（agent 或真人）。
2. 案例輸入、獨立答案、預期畫面與互動；D 可用明示的 mockup，P 必須來自實際 pipeline。
3. 當前全頁及重點畫面；viewport、縮放、資料版本、對應案例與重現步驟。
4. 填完的標準表、反例、待驗證事項與總判定。每個缺陷連到任務及畫面／測試。
5. 下一步只修影響目前任務的問題；新增功能需說明哪個既有成功條件無法滿足。

不要以文件存在視為驗收通過。已交付兩種可操作閱讀模式與合成 snapshots；最新證據見 [可攜版本 review](REVIEW.md) 與 [完整功能檢核](FEATURE-CHECKLIST.md)。本契約不因已有實作而自動通過，真人與產品整合仍待驗證。

## 8. 身分中斷與複製貼上（v1.2，使用者確認）

下列四項每次改動配對、fallback或呈現時必須驗收。持久ID是強證據，但不是唯一的內容比較依據。內容對應不得宣稱為持久身分或編輯操作歷程；不使用位置／相似文字猜測修改段落。

| 案例 | 可接受 | 不符合 |
| --- | --- | --- |
| P1 整頁複製、刪除、原樣貼回 | ID全部換新但完整保存內容與順序相同時，不誤報整頁新增／刪除；註明身分重建；媒體／未知內容仍保留未驗證 | 只因ID不同將相同內容整頁標紅；把媒體來源相同當內容已驗證 |
| P2 貼回後改一句 | 唯一且完整相同的區塊可建立內容對應；剩餘內容可定位、完整前後可讀；明示降級原因、範圍及沒有逐字差異 | 用位置或相似度假定一對一修改；只剩整份raw JSON；默默漏掉未知欄位 |
| P3 原文還在、額外貼一份 | 原ID優先；新增副本完整保留，不被相同文字去重或誤認搬移 | 合併相同段落導致新增副本消失；猜同一身分 |
| P4 大量重複條款、貼回後改一條 | 全文件重複區塊不得靠剩餘數量變成唯一；保留待核對區域兩側完整內容與各自順序，明示左右並非逐段對齊 | 依第幾段猜對應、虛構精準高亮或漏掉義務／期限改動 |

新增比較metadata須可機器讀取：每項配對依據、降級模式、精確內容對應數、兩側未配對數及內容對應順序是否不同。唯讀、未知內容提示、原始JSON與存取權不因內容對應而放寬。缺ID／重複ID／跨namespace仍依安全邊界處理，這輪不是無ID歷史回補或模糊配對。
